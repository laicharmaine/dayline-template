# Dayline

Your day on one calm screen: Notion to-dos, all your calendars, classes and clubs, and a job-search pipeline.
Runs free on Vercel with your own Notion. Works in a desktop browser and on your phone (Add to Home Screen).

**Not a coder? Follow [SETUP.md](SETUP.md)** (about 30–45 minutes, all clicking and pasting).

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Flaicharmaine%2Fdayline-template&env=APP_PASSWORD,NOTION_TOKEN&envDescription=APP_PASSWORD%20is%20the%20password%20you%20will%20type%20to%20open%20Dayline%20(10%2B%20characters).%20NOTION_TOKEN%20is%20your%20Notion%20internal%20integration%20secret.&envLink=https%3A%2F%2Fgithub.com%2Flaicharmaine%2Fdayline-template%2Fblob%2Fmain%2FSETUP.md&project-name=dayline&repository-name=dayline)

The button copies this template into your own GitHub account and deploys it to your own Vercel account.
It asks for two values: `APP_PASSWORD` and `NOTION_TOKEN`. Then open your new site, sign in, and the
**First-time setup** page creates your Notion databases and gives you the rest of the settings to paste.

## What each tab does

| Tab | What it's for |
|---|---|
| **Today** | Overdue and due-soon tasks, today's schedule from all your calendars, upcoming deadlines and job next steps |
| **Week** | A 7-day calendar with your events, deadlines and tasks |
| **Tasks** | Your Notion To Do list as an editable table: rename, set dates, area, priority, class/club tags, check off |
| **Jobs** | A board of roles you're pursuing (Interested → Applied → Interview → Offer), with optional resume tips |
| **Opportunities** | Roles you're still researching, sorted by fit or deadline |
| **Classes** | One card per class or club: its open tasks, upcoming sessions and Canvas deadlines, plus a sticky-note Brainstorm board |
| **Socializing** | Events from your social calendar plus lunch/dinner free time for the week; jot down who you're eating with |
| **Coffee chats** | People you've met and every touch point, with thank-you reminders and draft notes (Dayline never sends anything) |
| **Add from URL** | Paste a job link and Dayline fills in company, role, location and more for you to review |

Press `?` in the app for keyboard shortcuts.

## What lives where

- **Notion** (your workspace, through your own integration): To Do, Recruiting pipeline, Brainstorm, People,
  Touch points, and a small "App data" database Dayline uses for meal plans and reminders. Setup creates all six
  under one page you choose.
- **Calendars**: read-only, through each calendar's secret iCal (ICS) link. Add as many as you like with
  `CAL_1_URL`, `CAL_1_LABEL`, `CAL_2_URL`… (see `.env.example`).
- **Gemini** (optional, free key from Google AI Studio): smarter job-link reading, resume tips and thank-you drafts.
- **Your classes and clubs**: `config/classes.js` (edit on GitHub, Vercel redeploys by itself).
- **Your resume bullets** for tips: `config/resume-baseline.json` (the included one is a fictional example).

All settings are environment variables, listed and explained in **[.env.example](.env.example)**.

## Run it on your computer (optional)

Needs Node.js 20 or newer.

```bash
npm install
npm run demo            # fake demo data, never touches Notion: http://localhost:4320
npm test                # no network needed
```

Demo mode needs a password too: create a file named `.env` containing `APP_PASSWORD=pick-any-password`.

To use your real Notion locally, copy `.env.example` to `.env`, fill in `APP_PASSWORD` and `NOTION_TOKEN`, run
`npm start`, sign in, and open http://localhost:4320/setup. Or from the terminal:

```bash
npm run setup-notion -- --list                         # pages your integration can see
npm run setup-notion -- "https://www.notion.so/Your-page-…"  # creates the databases, prints the env lines
```

- Demo data is generated by `scripts/build-fixtures.js` (fictional companies, classes and events, dated around
  today). Edits in demo mode go to `data/fixtures/*.local.json`; `npm run demo` resets them.
- `NOTION_READ_ONLY=true` lets Dayline read Notion but blocks every write.

## For other assistants and automations: set "Added by" = Bot

Each Dayline database has an **Added by** select with options `Me` and `Bot`. Rows created in the app are `Me`.
Any assistant, script or integration that creates rows should set `"Added by": { "select": { "name": "Bot" } }`,
so you can tell them apart (there is an Added by filter on Tasks and Jobs).

## How it works

- `server.js` wires things up; `lib/app.js` holds the Express routes. Every page and `/api/*` route needs the
  password except `/login` and `/healthz`. Sessions are a signed cookie.
- Until `NOTION_DATA_SOURCE_ID` is set, the app runs in **setup mode**: after sign-in every page goes to `/setup`.
  `lib/setup.js` creates the databases (Notion API `2026-03-11`, `POST /v1/databases` with an
  `initial_data_source`), reuses ones it already made under that page, and returns the env lines.
- `lib/notion.js` and `lib/jobs.js` read and write rows through data sources; `lib/calendar.js` fetches the ICS
  feeds (cached 5 minutes), expands recurring events in your time zone and merges duplicates across calendars.
- `lib/jobparse.js` reads job links (Greenhouse/Lever APIs, schema.org JobPosting, optional Gemini, then page
  tags). Fetching is SSRF-safe: public IPs only, redirects re-checked, timeouts and size caps.
- Front end: plain HTML/CSS/JS in `public/`, no build step, strict Content Security Policy.
- Deploy: Vercel Hobby (free). `server.js` exports the Express app when running on Vercel.
